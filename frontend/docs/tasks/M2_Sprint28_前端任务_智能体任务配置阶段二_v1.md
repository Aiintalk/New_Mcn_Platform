## 1. 目标

在阶段一管理员页面上接入内容分析任务配置 V1.6 阶段二合同：持续保存共享飞书报告根目录；日测试按项目、周测试按去重账号选择；运行监控展示项目/账号执行对象、四层结果与分阶段重试。页面继续只对管理员开放，只保留“任务与输入 / 运行监控”两个页签。

## 2. 实现范围

1. 概览回显 `report_root_ref` 及配置状态，项目范围与报告根目录一次保存。
2. 报告根目录明确为内容分析智能体级共享配置，持续生效、不按项目保存、测试时不可临时覆盖；不提供两张飞书输入表配置。
3. 固定任务继续展示每日北京时间 00:00 / 3 个完整自然日、每周一北京时间 01:00 / 30 个完整自然日，并说明自动调度默认关闭、当前未正式启用。
4. 日测试可选择任何必要配置通过的项目，不要求加入持续自动运行范围；周测试也从全部入驻成功且必要配置通过项目汇总的账号候选中选择，并展示升序关联项目编号，测试弹窗不改变持续范围。
5. 每次新测试和手动重试生成新的 `request_id`；同一弹窗网络失败后再次确认复用，成功、关闭或切换执行对象后重置。周账号搜索、翻页或候选响应使原账号消失时，清空账号和请求号，必须重新选择。
6. 运行监控增加账号筛选，兼容阶段一 `retry`、阶段二 `manual_retry` 和系统 `internal_retry` 运行类型。
7. 列表与详情区分项目实例、账号实例和内部“周批次收尾”实例；收尾显示批次编号与账号数量，不能冒充账号实例。账号历史只展示脱敏哈希及关联项目编号，不展示完整账号标识。
8. 列表与详情展示数据库预检、飞书关系、内部结果、投递四层状态和失败阶段；`internal_result_id` 存在时显示只读“内部结果编号”，不伪造平台详情链接；内部结果为 `no_content` 时显示“无内容（空日报）”。
9. 只有合法的 HTTP/HTTPS `document_url` 才显示新窗口安全外链；没有结果时只显示“暂无结果”，不再伪造联调占位状态。运行结果区不展示账号明文或报告根目录引用。
10. 投递阶段失败只提供“仅重试投递，不重复分析”；其他失败提供“完整重试”。
11. 报告根目录未配置时，页面明确提示自动和测试任务只记录为未运行且不调用执行器；测试弹窗重复提示，但不阻止浏览周账号候选。

## 3. 接口合同

- `GET /overview`：新增报告根目录引用及是否已配置。
- `GET /weekly-accounts`：支持页码、每页条数、关键词和项目编号筛选。
- `PUT /config`：提交 `selected_project_ids` 与 `report_root_ref`。
- `POST /test-runs`：日任务提交项目和请求号；周任务只提交账号和请求号，前端不得提交项目列表或目录。
- `GET /runs`：增加 `account_key` 筛选，并读取执行对象、四层结果及失败阶段。
- `GET /runs` 的周任务记录还可能返回 `weekly_batch_finalize` 内部执行对象；前端只读识别，不新增页面写操作或 HTTP 接口。
- `POST /runs/{id}/retry`：必须提交请求号；投递重试模式由后端根据原失败阶段决定。
- 所有结构化请求继续走 `frontend/src/api/request.ts`，不直连飞书、模型或其他外部服务。
