## 一、任务目标

在不新增接口、数据表、迁移、调度、前端和真实模型调用的前提下，交付数据源与分析器均可替换的离线内核，用自动化测试锁定阶段一可以确定的计算、证据与项目隔离边界。

## 二、开发范围

1. 建立不可变领域对象，表达内容来源、稳定身份、最新互动值、证据、项目上下文、业务状态、日报和内容库候选。
2. 实现中国时区下的最近 3 个与 30 个完整自然日窗口、稳定键去重、人设点赞五项基准和播放量不可用处理；每个账号独立生成最近 3 日千川点赞前 3 池，接入主引擎后再按项目筛选 0—3 条机会。
3. 定义 `ContentAnalyzer`（可注入的异步内容分析协议），测试只使用模拟分析器；共享基础分析可复用，项目适配判断必须分项目执行。
4. 实现 `ContentAnalysisEngine`（离线内容分析编排器），输出项目日报、分类和互动概览、0—3 条人设/千川机会、待入库候选与方法级跨项目候选；候选门禁要求六类封闭价值信号（早期数据强、相对基准更优、新选题或结构、清晰流量钩子、可复用转化结构、值得关注的镜头表现）、覆盖项目人设/目标用户/内容规划/运营方向的结构化适配理由、视频引用与转写双证据，并与项目内已有库的全部稳定键比较。
5. 强制证据保护：缺少字幕可继续；视频不可读时不保留确定镜头或第一画面结论；来源商品说法不得升格为当前项目已确认事实。

## 三、数据与测试输入口径

- 本轮未在生产逻辑中读取飞书、日期表或本地关系快照，也未提交原始 2098 条数据。
- `phase1_anonymized.json`（阶段一匿名静态样本）只含 2 条最小匿名合成内容、1 条匿名项目关系和 1 份匿名项目上下文；不含真实账号、真实项目、长转写或内网地址。
- `test_adapter.py`（标准输入适配测试）会把上述样本转换为稳定领域对象并驱动一次离线引擎；多项目关系、上下文隔离和范围外账号不触发分析仍由 `test_engine.py`（离线引擎单元测试）覆盖。

## 五、明确不做

- 不做公共 API（应用编程接口）、正式数据接口、生产飞书读取、数据库/迁移、路由、调度、前端、真实项目验收。
- 不做可读视频的完整镜头验收，不调用真实或付费模型。
- 不生成公司级日报，不构造互动时间序列或增长趋势。
- 不实际持久化日报、基准、内容库或跨项目候选，不联调下游仿写读取。
- 不建设人工入库内容补标/回写、库生命周期、停用/恢复或编辑/版本能力。
