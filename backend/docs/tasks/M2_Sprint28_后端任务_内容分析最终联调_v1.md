# M2 Sprint28 后端任务：内容分析最终联调执行侧 v1

## 状态

内容执行侧单模块已经独立验收，并已进入专用最终组合联调工作树；当前组合快照仍处开发联合验收阶段，不代表真实飞书/模型联调、上线或发布完成。

## 已批准范围

1. 定义同进程任务信封及两个调用入口：完整执行/完整重试 `execute`，仅投递重试 `redeliver`；保留并校验 `retry.mode`，任务配置内部重试保留原窗口与截止时间并记为系统触发。信封各层及三种执行对象使用精确字段闭集，未知或跨分支字段失败关闭。
2. 用部署配置装配飞书多维表格真实网络客户端，完整读取固定内容表和关系表；项目任务、账号集合、窗口与共享报告根目录由任务配置注入。
3. 每日按单项目运行；周度账号实例携带排序去重后的项目编号及批次位置；账号全部终态后由正式域 `weekly_batch_finalize` 收尾实例汇总最新终态和已保存基准并更新公司周报，不重复读取输入、分析或业务投影。收尾携带非空 `finalize_version` 并写入不可变结果与来源回执；存在已选项目但账号数为 0 时仍执行收尾；项目范围必须非空。测试域只执行单账号，不创建收尾实例。
4. 复用既有离线引擎、`yunwu.chat` 和 `AiCallLog`；正式模型返回值必须经过领域对象校验。
5. migration 060 只创建结果、投递、项目库扩展、跨项目机会、账号基准五表；完整正文保存在既有 `outputs.content_json`。
6. 正式日报按数据库项目编号与项目名称派生目录；周账号只更新账号区块，收尾实例只更新公司汇总区块；两者复用稳定周报文档键。投递失败保留内部结果，只重试投递。
7. 提供项目库分页读取、人工加入、停用/恢复、千川开头人工补标接口；写操作记录 `OperationLog`。人工正文可不带作品编号和外部链接，持久化后使用项目库记录编号作为内部历史身份，不得因此阻断任一项目日报。
8. 测试运行只写测试结果及确定性测试目录，正式项目库、跨项目机会、账号基准零写入。
9. 提供可长期注册的运行入口，每次完整执行或仅投递重试独占数据库会话与飞书网络客户端，并在调用结束释放资源。
10. 系统内部重试以数据库原任务绑定执行对象、窗口、正式/测试域、测试子目录和三层幂等键；每日项目、周度账号和收尾的人工完整重试同时绑定本次重试 TaskJob 与来源失败任务，`manual_retry`/`retry` 两种真实字典别名等价，重试来源编号、模式、隔离域、测试子目录和请求编号按运行类型严格闭合。每日/账号人工仅投递重试还要绑定当前任务保存的请求编号、原失败投递、既有内部结果及完整原投递目标；连续补投逐跳校验来源链并始终定位同一不可变结果，周账号补投后收尾继续使用该结果。自动收尾执行以及系统/人工收尾完整重试和补投均在周批次锁内、任何结果读取或投递前核验最新版本，禁止投递失败升级成完整重试或旧版本覆盖新周报。完整或仅投递调用在参数解析、资源创建、系统配置或来源校验失败且尚未读取飞书时，飞书输入层标为跳过；仅投递仍返回投递层失败，内部结果标为跳过。同一分析键先以受截止时间约束的进程内单飞锁收敛，再与周批次、目录前缀和文档键一样使用会话级数据库锁实现跨进程幂等；同一任务嵌套锁复用一个独立连接，按连接池容量预留业务连接，非阻塞轮询不超过任务截止时间，且不受业务事务中途提交影响。跨项目机会首次查询/写入前取公司级事务锁；人工新增在稳定身份去重查询前，人工开头补标以及停用/恢复在读取候选前取同一锁，日报自动刷新和自动补标也纳入该锁；模型分析结束后在锁内重读当前可用状态和待补标集合再冻结日报，避免稳定身份重复、跨项目机会使用旧快照、停用内容继续出现在新增候选/在库/跨项目输出或单条失效补标进入日报失败明细并回滚整份日报。飞书文档键和周报区块键均使用哈希标记，并只按固定元数据行定位，业务文本和带换行的键不能伪造身份。停用记录继续占用稳定身份以阻止自动重复新建，但当天再次采集到时不恢复为可复用内容，不标记为跨项目，也不进入跨项目机会；必须经人工恢复后才能重新参与复用。

## 四种运行时映射

- 关系表完整读取但当前执行对象无有效关系：`not_run`。
- 关系表或内容表鉴权、字段、分页、超时或读取失败：`failed`，不得生成无内容报告。
- 有有效关系且内容完整读取，但窗口内零视频：内部 `no_content`；空报告投递成功后总状态 `success`。
- 有内容且读取完整：分析、事务持久化、投递均成功后总状态 `success`。

## 联调依赖

- 任务配置侧按共同信封构造每日项目实例和周度账号实例，并保存四层结果摘要。
- 任务配置侧负责在声明的全部账号实例终态后创建周批次收尾实例；即使最后一个或全部账号失败也必须触发，账号重试改变终态后再次触发新版本收尾。
- 失败周批收尾的投递重试只调用 `redeliver`，内容侧核验原任务投递失败、内部结果编号、同批次同权威版本；来源无效使用 `EXECUTOR_CONTRACT_INVALID` 保持仅投递上下文。非投递阶段失败可用 `manual_retry + full` 调用 `execute`，必须绑定当前重试任务与失败来源，禁止仅投递失败升级成完整执行或旧版本覆盖。
- 任务配置侧有已选项目但没有账号实例时，创建 `batch_size=0` 的收尾实例；完全没有已选项目时不创建任何账号或收尾任务。
- 收尾按每个成功/无内容账号任务绑定的内部结果编号核验不可变结果与基准正文，周报展示五项基准、更新时间、关联项目和安全失败原因；“没有可计算账号”按可用且样本数大于 0 的账号数判断。
- 管理员共享飞书报告根目录、系统服务账号、两张输入表标识、应用凭据和模型配置由部署环境提供。
- 两侧差异已在主产品经理指定的独立最终联调工作树组合；后续仍需组合快照三线复审与完整门禁，真实凭据和试点项目另行授权。
