# M2 Sprint26 后端任务：运营反馈缺陷修复 v1

> 开发状态：代码与聚焦测试已完成，等待全量门禁、独立技术复审和产品经理验收；未合并、未部署、未执行生产数据库操作、未上线。

## 目标

关闭千川脚本预审和千川脚本复盘中“没有有效业务结果却记为成功”的后端路径，让任务终态、错误响应和保存资格保持一致。

## 开发范围

1. 脚本预审结果严格校验评级、必改项和字符串数组；首次结构不合法时最多执行两次仅整理 JSON 结构的受控修复。
2. 脚本预审调用前创建任务，只记录模型、达人/商品编号和脚本长度；失败任务不写成功日志，成功响应返回任务编号。
3. 脚本预审保存接口重新校验结果结构，只接受当前用户的成功任务，并关联任务与产出。
4. 脚本复盘流统一为内容、完成、失败三类事件；空流、异常和中断分别记录真实失败终态。
5. 脚本和投放数据零匹配时在模型调用前返回行号/素材名诊断，不创建任务。
6. 脚本复盘保存接口拒绝错误标记和非成功任务，并关联任务与产出。

## 契约与数据边界

- 已更新 `backend/docs/base/MCN_M2_Base_API.md` 第 14、27 节。
- 未新增或修改数据库表、字段、索引、迁移和权限；继续复用现有 `task_jobs`、`outputs`、`operation_logs`。
- 任务追踪不保存完整脚本、报告或视频转录正文。

- 不执行生产数据库操作、部署、上线或合并主分支。
