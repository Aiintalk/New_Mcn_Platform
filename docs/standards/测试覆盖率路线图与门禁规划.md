## 0. 终极目标

## 1. 覆盖率阈值（分层目标，沿用 CLAUDE.md 体系）

| 层 | 目标 | 说明 |
|---|---|---|
| Models | ≥ 90% | 纯数据模型，易测，高标准 |
| Core（config/security/response/database） | ≥ 85% | 基础设施，当前已基本达标 |
| Services | ≥ 80% | 业务逻辑核心，重点投入 |
| Routers / API | ≥ 70% | HTTP 契约层 |
| Adapters | ≥ 60%（宽松） | 外部服务封装，真实调用难测，以 mock 集成测试为主 |
| 整体 | ≥ 75% | 项目级底线 |

> 阈值在门禁启用时落入 `scripts/run_coverage.py`，可分层配置。

---

## 5. 风险与注意

- **覆盖率 ≠ 测试质量**：仅 happy path 的测试即使数字达标也不够，门禁配套要求覆盖正常 + 错误 + 边界（见 CLAUDE.md TDD 章节）
- **adapter 阈值宽松**：外部服务封装不应为凑数而硬测 mock，60% 阈值合理
- **门禁渐进**：先"量不卡"→"增量门禁"→"全量门禁"，避免一次性卡死历史代码（参考 corp 覆盖率策略）
- **测量口径统一**：覆盖率数据必须基于**全量 `pytest tests/`**（unit+integration），而非窄范围跑，否则严重失真
