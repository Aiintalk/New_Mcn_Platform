## 3. 未达标根因（诚实说明）

5 个未达标路由的**未覆盖代码集中在三类，均不属于 HTTP 契约层**：

1. **后台任务体（报告生成）** —— 占未覆盖行的大头，也是 intake_public(+6)、operator_intake_direct(+10) 提升甚微的主因
   - `intake_public.generate_intake_report`（约 365–497 行，133 行）
   - `operator_intake_direct._generate_operator_session_report`（约 490–597 行）
   - `operator_benchmark.save_results`（SSE 后台写库体）
   - 这些函数内部调**真实 AI + docx/pdf 文件生成**，集成测试用 mock 替掉，函数体未执行。**只能通过 service 层 unit test 覆盖**。→ 这就是为什么 intake_public 加了 37 个测试、operator_intake_direct 加了 44 个测试，覆盖率却几乎没动：测试命中了端点契约层，但碰不到被 mock 掉的 service 体。

2. **`admin_ai` stats 的 raw SQL 聚合分支**
   - `/stats` 的 `service_status` 4 分支（healthy/degraded/overloaded/unavailable）+ token_trend/by_model 聚合
   - 集成测试已覆盖**结构契约**（返回 summary/by_model/token_trend），但**逐分支命中**需 seed `ai_call_logs` 数据。

3. **大型 helper 函数**
   - `operator_intake_direct._build_full_system_prompt`（多分支拼装）—— 适合 unit test，集成测试难逐分支穿透。

**结论**：本轮 router 集成测试已把 **9 路由的 HTTP 契约层（鉴权 / 信封 / 错误码 / 分页 / 用户隔离 / happy + error path）全覆盖**；剩余 gap 在 **service 层逻辑与 SQL 聚合分支**，需 Round 2 的 unit test 才能拉到 70%。这是架构分层决定的，非漏测。

## 5. 测试方法

- **集成测试**：`httpx.AsyncClient` + `ASGITransport`，真实路由 + 真实 auth 中间件 + 真实测试库（PostgreSQL `mcn_test`）
- **DB 隔离**：`test_session` fixture 全局 patch `AsyncSessionLocal`（含全部 9 路由模块），不碰生产库
- **外部 adapter 全 mock**：`yunwu` / `tikhub` / `oss` / `httpx`（`unittest.mock.AsyncMock` patch 源头模块）
- **后台任务 mock**：报告生成类 BackgroundTask 用 AsyncMock 替掉
- **autouse 清理 fixture**：解决 `config_key` unique 约束 + 跨测试数据污染
- **响应信封断言约定**：
  - `success_response` → HTTP 200 + `success=true`
  - `error_response` → HTTP **200** + `success=false` + `code`（不改状态码）
  - `HTTPException` → `app/main.py` 全局 handler 改写信封但**保留真实 HTTP 状态码**
